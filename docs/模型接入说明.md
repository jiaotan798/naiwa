# 模型与资源维护

奶蛙的模型和动画源文件是 [nailong_origin_zero.bbmodel](../assets/source/nailong_origin_zero.bbmodel)。Blockbench 采样高模和 11 段动画，再从高模派生低模。游戏读取 `assets/runtime/` 中的采样文件，整蛊时会叠加程序动作。 [模型与法线来源](../assets/source/README.md)

## 校验和采样

普通构建会校验源码模型、法线和采样文件的 SHA256。也可以在仓库根目录单独检查。

```powershell
node ./scripts/bake-model.mjs --check
```

替换模型时，使用 Node.js 22 或更新版本，安装 Blockbench 5.2.1，并让 `BLOCKBENCH` 指向启动文件。采样脚本使用独立的 `.bake-work/` 用户目录和回环端口，结束后关闭自己启动的编辑器。

```powershell
$env:BLOCKBENCH = 'C:\工具\Blockbench\Blockbench_5.2.1_portable.exe'
node ./scripts/bake-model.mjs
./scripts/gradle.ps1 build
```

如果高模和采样清单已匹配，可运行 `node ./scripts/bake-model.mjs --lod-only` 重建低模。这一步不用启动编辑器。

- 源模型的脚底为零，16 个编辑单位对应游戏里一格。飞升高度由服务端控制。
- 采样以约 50 Hz 记录原生动画矩阵，游戏端负责插值和蒙皮。换模型时要一起核对手指归属、道具定位和颈部切面。
- `model-manifest.json` 记录输入和产物的摘要，`native-pose-checks.json` 保留 33 组原生姿态对照。两份文件用于构建校验。

## 盾牌资源

[盾牌源图](../assets/shield/naiwa-shield-v1.png)有自己的 UV，换图时要检查盾面、把手的取样矩形和透明边界。头部从实体网格的颈部以上裁切。后脑也受颈骨影响，单按头骨权重筛选会漏掉后脑。盾面和头部都朝局部 +Z，换模型后要复核切面、后脑及探头高度。

## 音效

完整大笑由 0.6 秒入场、8.25 秒大笑和 0.8 秒恢复组成。`laugh_full.ogg` 保留约 1.44 秒准备静音，动作与笑声在整段演出约 2.04 秒时起拍。盾牌探头约 0.3 秒后播放 `laugh_short.ogg`，持续 1.7 秒。

普通构建无需 FFmpeg。把 FFmpeg 加入 `PATH` 后，可运行 `node scripts/verify-laugh-sync.mjs` 检查音轨时长、起拍和收尾。调整静音段时，同步核对动作起拍。 [音轨来源](../THIRD_PARTY_NOTICES.md)

## 飞升特效

金色光束随角色朝向转动。地面光斑随玩家横移，高度取起飞时的脚底。雨丝接近光轴时从灰蓝过渡到金色，最后随圣光渐隐。飞升阶段、碰顶和落地规则见[奶蛙图腾](完整玩法说明.md#奶蛙图腾)。

1.21.1 NeoForge 的 `NaiwaAscensionShapes` 提供几何和受光数据，`NaiwaAscensionVisuals` 在世界绘制后依次画角色和透明特效。Iris 可能在着色器应用时切换画布，`NaiwaWorldShader` 在应用结束后重新绑定主画布。角色写入深度，透明圣光保留深度测试，这样地形才能正常挡住飞升画面。

`NaiwaAscensionBloom` 从场景颜色副本提取暖色亮部，双向模糊后合成。颜色副本避免同时读写一张纹理。窗口变化时同步缓冲尺寸，效果结束、换世界或着色器重载时释放自有缓冲。第一人称手部由 `NaiwaPlayerRenderer.hand` 在飞升期间接管，结束后交回原版。 [光影验证范围](../validation/0.5.0.md)

## 玩法维护入口

| 改动范围 | 对应代码与检查点 |
| --- | --- |
| 十种整蛊和临时奶蛙 | `NaiwaPranks` 负责共享间隔、场景清理与复活嘲讽。玻璃、船和箱子保留原版交互。 |
| 钻石诱饵和钓鱼 | `NaiwaDecoy` 暂存原钻石掉落。钓鱼在 `FishingHookMixin` 完成最终取消检查后再拦截渔获，NeoForge 的 `getDrops()` 返回副本。 |
| 奶蛙盾 | `NaiwaEncounters` 查找安全站位，`NaiwaEntity` 转化原盾，`NaiwaShield` 累计格挡并排队结算。`naiwa:shield_charge` 随物品保存，演出时间仅同步到客户端。 |
| 笑气瓶 | `NaiwaEntity` 的自动和手动收集共用单轮次数。投掷由 `LaughGasItem` 和 `LaughGasProjectile` 结算，粒子由客户端绘制。 |
| 保命、飞升和同步 | `NaiwaGameplay` 处理保命和飞升阶段，`NaiwaFlightHeight` 与网络注入同步高度并保留横移。`NaiwaEffectSync` 给旁观者补发剩余效果时间。 |
